# Retrospectives

The README's roadmap lists pending work only. This page keeps the record of how items left it, newest round first, because the recurring lesson is worth more than the list: "blocked" rots in both directions, so gates must be re-verified live rather than trusted from the record — and the engineering that actually remained was found by auditing the code, never by reading the list.

## 2026-09-16 (Examples round)

*Five use cases were written into the Examples repository, closing the last row the seven-round sweep had left open — and writing them found two bugs in shipped code that the test suite had been passing over.* Row 6 asked for a self-contained Lennard-Jones case, which now exists; the remaining rows renumbered 7-16 to 6-15. The useful pattern of the round is that every one of these defects was invisible to a passing test, and each was caught by making a case state a claim that could actually fail.

*The first bug was a test that checked a quantity invariant under the error it was meant to catch.* The compliance helper's `ConstraintChannels` wrote the support mask along the bottom edge and the load at the x-midpoint of the top edge, while the solve clamps `x = 0` and loads the far-x edge at the requested height — the conditioning channels were transposed against the problem they described. The test asserted each channel's **sum**, and a sum does not change under a transpose, so it had always passed. A conditional generative model trained on those channels would have learned a confident mapping from the wrong description of the problem. The second bug was a dtype gap on a path the unit tests never exercised with real geometry: boundary meshes built from a Kratos model part carry float64 point coordinates beside float32 cell data, and a float32 GLOBE then fails inside the matrix multiply. `RunGlobeForward` now normalizes the meshes to the model's dtype, with a regression test that fails without the fix.

*An assertion without a margin tests nothing, and looks exactly like one that does.* The diffusion-posterior-sampling case first shipped with `guided < unguided`, which passed — on a difference of 0.07 %, because at `std_y = 1.0` the guidance term is effectively off and the two ensembles agree to four significant figures. The sweep that replaced it shows the whole shape: guidance is silent above 0.1, works at 0.01 (5.95x), returns **finite and meaningless** values at 0.003, and raises at 0.001. A band where the numbers are finite and wrong is more dangerous than one that raises, and only a sweep makes it visible. The same case produced the round's second discipline: a guidance operator that borrows solver state has to give it back **on the failing path too**. The residual operator writes the trial field into the model part and restores it afterwards, which is correct until the sampler raises, at which point the exception escapes before the restore and leaves the model part silently modified. The end-of-script check that the field comes back bit-identical is what caught it; the restore now lives in a `finally`.

*Two measurements corrected assumptions that would otherwise have been written as facts.* A structured triangulation has **no mirror symmetry**: mirroring a topology design in y is exact for the continuum problem, because the clamp is symmetric, but `StructuredMeshGeneratorProcess` splits every cell with a diagonal running the same way, so the flipped design sits on a different structure. The gap measured 1.7 %, and was attributed rather than tolerated by flipping a *uniform* field, which is trivially symmetric and moved by 2.98 % — the mesh alone accounts for more than the whole discrepancy. Separately, under SIMP with p = 3 the modulus goes as rho³, so "the generated design beats a uniform field" is a bar almost anything clears and is not evidence of anything; the honest control is a volume-fraction-matched random structure. Reported against it, the generated designs win by 2.6x to 5.0x — and against the optimizer that produced their training data they lose by 3x to 5x, which the case states plainly.

*Two smaller traps worth recording.* A unit test's hyperparameters are not a starting point for a model that has to generalize: at the size the GLOBE test uses, the operator here collapses to predicting the field mean exactly, having learned the dataset's average and nothing about the boundary in front of it. And `MPLBACKEND=Agg` set in the environment causes scripts and notebooks to exit 0 having produced **zero figures**, which no assertion about numbers will ever notice.

## 2026-09-16 (the seven-round sweep)

*Seven rounds closed twenty-one of the roadmap's thirty-seven rows, and the two most useful outcomes of the whole sweep were refusals.* The brief was to close everything gated **open**. Rows 9-24, 26 and 29-35 are gone from the list, and row 6 lost its notebook half; what stayed, stayed for a reason now written into the row rather than into someone's memory. The pattern across the seven rounds is that the roadmap was wrong about upstream roughly as often as it was wrong about this application — three of its claims about physicsnemo 2.2 turned out to be false when checked against the installed package, and each is corrected below.

*The diffusion bridge left the deprecated API, and the two capabilities that were supposedly blocked behind that migration fell out of it rather than being built.* `WrapDiffusionModel` adapts a denoiser to `physicsnemo.diffusion.DiffusionModel`, training runs `MSEDSMLoss` over an `EDMNoiseScheduler`, and sampling runs `samplers.sample` with its four solvers; `"api": "legacy"` still reaches the deprecated modules because 2.2 ships no protocol equivalent of CorrDiff's `RegressionLoss`/`ResidualLoss`, so `"auto"` routes those two losses there. Deleting `_VolumetricEdmLossSR` was the pleasant part: `MSEDSMLoss` is rank-agnostic, so the local clone that the legacy loss's `randn([B, 1, 1, 1])` had forced is simply gone. On top of the migration, **DPS guidance** steers an already-trained denoiser toward masked measurements or any differentiable forward operator — the shipped operator being the exact discrete FEM residual, so the solver's own physics grades the generator with no retraining — and **multi-diffusion patching** samples a grid larger than the training resolution. The migration also surfaced a bug in shipped code that had nothing to do with diffusion: `InterpolateGridAtPoints` crashed on a **flat** bounding box, which is to say on any planar Kratos case, because a zero extent gives NaN fractional coordinates and NaN cast to an index is `INT_MIN`.

*The point-cloud round lifted a gate the roadmap had written as a warning to itself.* Row 14 said GLOBE's cluster-tree kernels should be verified on CPU "before anything else"; they build, forward and backpropagate there, so the row closed instead of stalling. Alongside it, a `"subsampling"` block gives the transformer a token budget with the unselected nodes taking their nearest selected node's prediction, and two genuinely non-pointwise interfaces arrived: `"deeponet"` mapping case parameters to a field at the nodes, and `"globe"` mapping boundary data to the interior. The geometry guardrail is the round's cautionary tale, because upstream's failure modes were all silent: it saves with `numpy.savez` and loads with `numpy.load`, so a sidecar named `guard.pt` is written as `guard.pt.npz` and can never be read back; its descriptor vector is 22-wide, so a family smaller than that fits an under-determined density model whose verdicts stop meaning anything without any complaint; and it measures descriptor *distance*, not plausibility, so a family of perturbed boxes rejects the perfect cube.

*The mesh round's most valuable result was a measurement that said "do not switch".* Row 20 asked for torch-native BVH sampling to be measured against the Kratos locator before anything was changed, and the locator won by 2-3x (795 ms against 1767 ms on a 64³ lattice over 196,608 tetrahedra). So the default stays `"kratos"` and the BVH path is kept only for the gradient it carries, which the locator cannot. The round also found the roadmap quoting upstream's own module layout wrongly: `shrinkwrap` and `sobolev_deform` live in `mesh.transformations.deform`, not `nn.functional`. Two upstream behaviours that raise nothing: mean and Gaussian curvature are NaN at every interior node of a volume mesh (zero vertex area), and `VTKReader` is not a general reader at all — it knows a fixed external-aero key vocabulary and returns an **empty sample** for a field called `PRESSURE`, which is why the shipped path reads fields by their own names through `mesh.io.from_pyvista` instead.

*The metrics round answered a question pointwise error cannot.* `histogram_l1` and `entropy_difference` compare the two fields' distributions on shared bin edges, and a `"spectral_comparisons"` block compares azimuthally averaged power spectra, because a surrogate can match a field on average while collapsing its extremes: the test pins a smooth prediction of a rough field scoring an RMSE below 0.2 while carrying under a tenth of the reference's fine-scale energy. Here the roadmap was wrong about upstream a third time — physicsnemo 2.2 has **no** `relative_mse` whatever the row said, so it is implemented locally — and upstream's *normalized* `entropy_from_counts`, documented to map onto [0, 1], returns about -0.9 for a delta, so the metric uses the unnormalized form. The distributed half produced the round's sharpest lesson: **gloo cannot do a ragged all-to-all**, and a halo is ragged by definition (many rows to the interface neighbour, none to itself). A uniform probe hid that completely — two rows between every pair passed while seven-and-zero failed — so the test now asserts the exchange really is ragged *before* asserting that it works.

*The architecture round shipped three recipes and refused a fourth, which is the entry worth reading.* DPOT, TopoDiff on a real SIMP compliance solve, and AeroJEPA pretraining all landed. Item 27, equivariant surrogates, did not, and the row was narrowed and re-gated rather than quietly dropped: with the grid mask applied correctly, `rotate_grid_coefficients` moves the l=0 scalar part (2.6), fails to preserve the l=1 norm (7.0), round-trips under neither inverse convention and does not commute with a z-rotation. A rotation that moves the scalar part is not a rotation, and four probes did not find the convention that makes it one. Shipping something labelled "equivariant" whose equivariance could not be demonstrated would have been worse than saying so. AeroJEPA carries the round's other negative, and the test records it instead of tuning until it disappeared: after six epochs the pooled descriptor does **not** separate spheres from boxes — 0.74 between classes against 2.00 within.

*Seven compiled Kratos applications went from "imports cleanly" to "has a case", and the cases exposed two defects in shipped code.* `PinnSolveProcess` sized its network from the PDE field widths and its boundary mask from the Kratos variable widths — equal for a scalar, so every diffusion test had passed, but two against three for a 2-D velocity, so every 2-D vector PINN failed on a shape mismatch. And `nurbs_sampling` accepted only concrete `NurbsSurfaceGeometry3D` objects, so it could sample geometries built by hand but not the Brep wrappers an IGA *analysis* produces — the one case the isogeometric gather exists for. The cases reuse each owning application's own test data in place rather than copying it, which keeps a 216 kB cylinder mesh out of this application and stops fixtures drifting from their sources. The traps found were uniformly quiet ones: dropping a borrowed case's `processes` block also drops its boundary conditions, so the cylinder completes instantly at a maximum velocity of exactly zero and reads as a fast case rather than an undriven one; a nodal `POINT_LOAD` without a point-load *condition* returns zero displacement and a compliance of exactly zero, which reads like a converged answer; `IgaApplication`'s `single_patch_test` is structurally singular, its configured iterative solver returning NaN without complaint, which its own test never notices because it asserts nothing numerically; and the compressible NACA case has no angle of attack at all — it is parameterized by Mach number, so sweeping an angle would have produced identical solves and a surrogate that appeared to have learned something.

*The notebook round ended on a trap in the tooling rather than in the code.* Notebook 20 walks the Lennard-Jones recipe end to end, and its one asserted claim is the deployment one: a force RMSE of 0.1716 against the mean-force predictor's 0.3633, chosen because a model ignoring its de-normalized inputs could still predict the mean force everywhere. The trap was in committing it: executed under `MPLBACKEND=Agg`, `plt.show()` warns and emits no output, so the first pass produced a notebook that exited cleanly with **all four of its figures missing**. Every notebook here is committed with its outputs, so "the run succeeded" was not the same question as "the artifact is correct".

*What did not move, and why it is still listed.* The three hardware rows are unchanged — one GPU, no runner — so the NCCL transport and the CUDA-only `ShardTensor` paths remain asserted over gloo only. Upstream's 3-D `fill_interior` still raises `NotImplementedError`, the NIM still needs an NGC key and docker, and physicsnemo-cfd's benchmark engine still does not import. Rows 7 and 8 stay open in the plainest sense: they need a crash dataset and furnace/AM trajectories at scale, which is data this environment does not have, and no amount of engineering here substitutes for it. Row 6 kept its Examples-repository half deliberately. The one row that changed character rather than status is the aerodynamic surrogate: the surrogate shipped and the adjoint dispatch is pinned as resolving, but the cross-validation needs the separate adjoint solver and primal-restart files the owning application builds for its own regression, so the row was narrowed to exactly that.

## 2026-09-02 (documentation and roadmap)

*A documentation round, and a re-baseline of the roadmap against the whole 2.2 surface rather than against its own history.* The documentation had grown page by page with each feature and had no diagrams at all; this round added an architecture, a lifecycle, a ModelPart-to-DomainMesh mapping and an execution-points timeline to the General section, one concept figure to every PhysicsNeMo Basics page (checkpoint anatomy, the datapipe stages, the mesh data model, the three residuals, the diffusion split, data versus domain parallelism, the layer taxonomy, the uncertainty decomposition, where the time goes), five new Basics pages (layers and functionals, uncertainty and guardrails, active learning, training utilities and performance, versions and compatibility), and eight new General pages (architecture, Kratos concepts for ML readers, a process reference of all twenty-six processes with their defaults, installation and environment, performance, testing and contributing, troubleshooting and traps, a glossary), plus a gallery of the twenty-one Examples use cases. Two static guards joined the suite for it: every relative link and image in the pages must resolve, and the figure generator must still produce its files - because a documentation tree with forty figures rots exactly the way a test suite does, silently.

*The roadmap was re-derived from the installed 2.2.0 module tree and changelog instead of from the previous list.* That found twenty more items than the eight the list held, in two groups. Upstream capabilities the bridge does not reach yet - first among them that the diffusion bridge runs on modules upstream now marks for deprecation, which gates DPS guidance and multi-diffusion behind a migration - and eight Kratos applications that are compiled and import cleanly in the reference build without a case behind them (RANS, CompressiblePotentialFlow, GeoMechanics, Poromechanics, Dam, ContactStructuralMechanics, Iga, MeshMoving). One gate was found stale in the other direction: physicsnemo-cfd's benchmark engine is declared but does not import in the installed source clone, so that item is upstream-gated rather than open. A new gate kind, *build*, names the applications the reference build does not compile.

## 2026-09-02

*The 2026-09-02 round re-verified the two remaining "blocked" architecture items live, and both gates were wrong in the same direction.* The `ShardTensor` item said a CPU mesh "trips `DistributedManager`" — true of `DistributedManager.initialize_mesh` (a CUDA mesh whenever a GPU is visible) and of `scatter_tensor`, and of nothing else: `ShardTensor` needs only a torch `DeviceMesh`, `init_device_mesh("cpu", ...)` provides one, and upstream's op handlers register on a CUDA-less host once asked to. So `distributed/domain_parallel_utils` ships — a Kratos field's owned rows as one uneven-sharded tensor, the halo-exchanging convolution on a sharded grid, write-back to owners then ghosts — asserted at np=2/3 over gloo like the FSDP2 checkpoints, with the one genuinely new fact pinned as a trap: the backward of a mean over a `ShardTensor` already leaves the **serial gradient on every rank**, so a DDP-style all-reduce on top is wrong by the rank count. The Lennard-Jones item said "no molecular architecture exists"; NVIDIA's own Lennard-Jones example uses the generic `MeshGraphNet`, and the actual gap was a periodic neighbour search, which `particle_bridge` now has (`"box_size"`, minimum image, scipy `cKDTree`), fed by a numpy velocity-Verlet reference in the `shallow_water_reference` mould — whose Störmer-Verlet recurrence makes the dataset's central-difference targets equal the reference forces to round-off. What did not move: the NCCL transport (one GPU), upstream's 3-D `fill_interior`, and the live NIM.

*The de-normalization bug class had two more instances, found by reading the write path rather than the roadmap.* The co-simulation surrogate wrapper and `SurrogateResponseFunction` were documented as covered and passed no normalization at all; the graph, time-series and grid processes never read the key. All apply it now, the response function inside its autograd objective (so `dJ/dX` carries the training scale — which is also why `ApplyOutputNormalization` became torch-native: the numpy round trip was returning CUDA predictions on the host and cutting every gradient). The symmetric `"input_normalization"` key closes the other half — the measured 18% particle drift from a model trained on standardized velocity histories and deployed on raw ones. Every one of the twenty-odd new tests is pinned by a mutation that removes the call, since the first draft of one of them passed with the call removed: it checked the value only after a gradient pass that recomputed it correctly.

## 2026-09-01

*The 2026-09-01 round closed five items, and the recurring lesson was that "blocked" rots in both directions.* Re-verifying every gate live found three worth acting on beyond the volumetric denoiser the previous audit had already flagged: pip wheels for `usd-core` (the self-contained Pixar USD — the "Omniverse export" item never actually needed Omniverse to *write*) and `tetgen` closed the digital-twin and exact-boundary-recovery items as optional dependencies; the IGA item's real gate turned out not to be the build at all — core Kratos already binds `NurbsSurfaceGeometry3D`/`NurbsVolumeGeometry`, constructors, `GlobalCoordinates` and `CreateQuadraturePointGeometries` to Python, so `nurbs_sampling` runs and is tested against core alone (IgaApplication is now compiled here too, but only the modeler workflows need it); and the NIM item's request schema — the one thing the roadmap said was missing — is simply published in NVIDIA's NIM docs (multipart `design_stl` upload, `.npz` response), so the client and process shipped with the payload contract pinned against a stub transport. What did NOT move: running a NIM still needs an NGC key and docker, so live verification stays gated (`TestNimLive` self-skips until `PHYSICSNEMO_NIM_URL` is set), and upstream's `fill_interior` n = 3 still raises `NotImplementedError` — the tetgen backend closes the *need* locally, deliberately as an explicit `"method": "tetgen"` opt-in (AGPL, and an installed optional must not silently change results), with the Schönhardt polyhedron now a real fixture instead of prose: the Delaunay route's failure on it is pinned, and tetgen fills it with one interior Steiner point at exact volume.

*The volumetric-denoiser item shipped as predicted "ordinary work", with one upstream surprise.* `denoiser_interface: "unet3d"` wraps `DiffusionUNet3D` for the same sampler/loss machinery as `"dit"` — but conditioning is passed natively through the model's `TensorDict` `"volume"` key instead of channel concatenation, and the legacy `EDMLossSR` turned out to hard-code the 4-D image rank (`randn([B, 1, 1, 1])`), so 5-D volumetric batches train through a rank-generalized clone selected automatically by sample rank; the 2D CorrDiff losses reject volumetric input with a clear error instead of broadcasting nonsense.

*The adjoint-integration item has shipped, and the useful part was the row order.* The gradients themselves already existed on both sides — Kratos's adjoint stack and this application's `sensitivity_utils` — and had even been cross-validated against each other. What was missing was an *interface*: Kratos reports a gradient as a `{entity_id: value}` dict, keyed by an adjoint model part whose iteration order need not be the primal's, and every other quantity in this application is a row-ordered array. `adjoint_bridge` converts by id, so a gradient lines up with a field by construction, and that one conversion is what makes an adjoint usable as training data. Two things then followed almost for free: a process that writes dJ/dX into an ordinary Kratos variable (so every existing exporter carries it), and a loss term that reads it back out. The measured payoff is the surrogate's derivatives, which a value-only fit never looks at: 4.8x lower gradient error at the same architecture, seed and data. The one genuinely new number was the second physics — ConvectionDiffusion's `AdjointDiffusionElement` agreeing with the shipped adjoint to 1e-6 once the objective normalizations were made to match, which they initially did not: Kratos's `point_temperature` averages where `weighted_sum` sums, a factor that looks exactly like a wrong adjoint and is not.

*The CuPy item has shipped, and the answer was "in four places, not everywhere".* `utilities/array_backend_utils` is the shared selector: `ResolveArrayModule` returns numpy or CuPy, `ToHost`/`ToDevice` move between them, and `AsTorchTensor` hands a device array straight to torch through DLPack instead of the device-to-host-to-device bounce the `torch.from_numpy(...).to(device)` idiom pays. **numpy is the default and `"auto"` resolves to it** — CuPy is opt-in per call (a `"backend"` setting) or process-wide (`KRATOS_PHYSICSNEMO_ARRAY_BACKEND`, `SetDefaultArrayBackend`), because it reorders floating-point reductions and installing it must not silently change anyone's results. Each converted site also carries a measured size threshold and falls back to numpy below it, since a host-to-device round trip costs more than the arithmetic on a small mesh.

Measured on one RTX 2000 Ada, 15625 nodes / 82944 tets, transfers included (`benchmarks/benchmark_bridges.py --backend both`): `particle_bridge` brute-force proximity graph **2.1x** (the quadratic distance matrix, rebuilt every step — the one unambiguous win, since the work grows as N² while the transfer grows as N); `graph_bridge.ComputeEdgeFeatures` **1.7–4.4x**, the ratio falling as the edge count rises because the edge index has to cross the bus on every call; `grid_bridge.InterpolateGridAtPoints` **11.6x** on a 3-channel 64³ grid at 100k points, but **0.7x** on a 1-channel 48³ grid at 15k, which is what the threshold is for; `rom_bridge`'s Φᵀu/Φq **6.7x at 1e7 basis entries and 7.8x at 2e7**, within noise of numpy below 1e7 (the basis is uploaded once and kept resident, so only the vector crosses the bus per step).

*And the honest negatives, which are the more useful half.* The provenance gather/scatter and `AggregateCellField` paths were converted, measured and **reverted**: 0.74–0.97x for the nodal gather and 0.49–1.42x for the cell reduction. Their operands live in Kratos-owned host buffers that must be re-read every step, so the transfer is the same O(N) as the arithmetic and no crossover exists. `model_registry.ApplyOutputNormalization` was left alone too — its torch→numpy→torch round trip was genuinely wasteful on a CUDA prediction, but the fix there was to do the arithmetic *in torch*, not in CuPy (since done: a tensor now stays on its own device and dtype with the autograd graph intact, which turned out to matter more than the copy — the round trip had been silently returning CUDA predictions on the host and cutting every gradient). What did pay on those paths was pure numpy: replacing the `{id: row}` dicts and `numpy.fromiter` generators with `searchsorted`, and `numpy.add.at` with `bincount`, made `GatherNodalField` **15x**, `ScatterNodalField` **10x** and `GetPointIndices` **6.7x** faster with no new dependency — which moved the nodal gather/scatter lines quoted in the profiling paragraph at the end of this page from 0.11–0.83 µs/entity to **0.03**, and grid sampling from 3.5 to 3.27. The lesson the roadmap item was really asking about: most of what looked like array cost here was interpreter cost.

*The two documentation-and-layout items have shipped.* `python_scripts/` is now a tree of packages (see [Where things live](Module_Map.html)), so a module's folder says what kind of thing it is and everything with a `Factory` lives under `processes/`; the tests, the eighteen notebooks, the docs pages and the Examples repository were rewritten onto the new paths, and a guard resolves every documented module path and every `"kratos_module"`/`"python_module"` pair against the real tree so they cannot silently rot. And [PhysicsNeMo Basics](https://kratosmultiphysics.github.io/Kratos/pages/Applications/PhysicsNeMo_Application/PhysicsNeMo_Basics/Overview.html) documents NVIDIA PhysicsNeMo itself across nine pages, joined by a module map and a from-scratch walkthrough — the gap being that everything here assumed the reader already knew what a `Module`, a `.mdlus`, a datapipe or a `DistributedManager` was.

## Earlier rounds (2026-08-26 to 2026-08-31)

*What has shipped.* The formerly "unblocked wins" are all in — GeoTransolver/FLARE, ONNX, `torch.compile`/NVTX, the CoSimulation `solver_wrapper`, the uncertainty-and-governance layer, the grid-operator zoo, DoMINO deployment and the `domino_finetune` predictor-corrector and LoRA recipes, DiT denoisers, the Lagrangian particle surrogate, and the complete physics-informed/differentiability layer: `PhysicsInformer` training terms with elasticity/Navier–Stokes builtins, `PinnSolveProcess`, and — the item long marked *blocked* — the `torch.autograd.Function` through the real FEM assembly plus exact adjoint sensitivities (`differentiable_residual`/`sensitivity_utils`).

The `physicsnemo-curator` ETL bridge has also landed — `curator_bridge` supplies the source side (the sinks ship upstream) and `CuratorExportProcess` writes Zarr/VTU straight from a running solve. Curator stays an optional, git-only dependency whose build pulls a Rust toolchain, so nothing here requires it: without it installed the bridge still imports and only its entry points raise.

That last gate moved without waiting for `kratos/future/`: the classic `CompressedMatrix` already exposes the CSR triple as (value-)zero-copy views consumed by core `scipy_conversion_tools.to_csr`, and the block builder's `Build`/`BuildRHS`/`ResizeAndInitializeVectors` are pybound (the native `CsrMatrix` with `SpMV`/`TransposeSpMV` is the forward-looking path).

So are the rest: the new-physics-domain recipes (GraphCast grid surrogates, test-pinned and gated only on `torch_sparse`/`dgl`; the CorrDiff two-stage regression+residual pipeline; FWI-style diffusion inversion); the mesh-and-data rounds (discrete calculus and grid derivatives, residual-driven MMG adaptive remeshing, coherent dataset augmentation/mixing, and the transient layer — real time-loop solver cases, temporal training schemes with BPTT, and the differentiable residual extended to dynamic schemes); the scalable external-aero GNN variants (bistride multiscale, mesh+world hybrid, KAN) and the Triton serving export; and the distributed extensions of the serial machinery — halo-partitioned graph training and the MPI-distributed co-simulation surrogate. The application now tracks **physicsnemo 2.2**, which unblocked and shipped the differentiable shape-deformation layer, mesh signed distance fields and the grid divergence/curl/Laplacian operators — and whose mesh-calculus gradient-layout flip is absorbed behind the bridge's own stable contract.

*How the gates were checked.* Re-verifying them once network access returned found three stale — the CUDA-13 ONNX wheel now exists, Kratos publishes application wheels that make an offline vertex-morphing reference possible, and the DoMINO checkpoint is public and ungated; all three are reflected in the shipped features.

*Where the real work came from.* The engineering that actually remained was found by auditing the code rather than by reading this list — the de-normalization bug class, of which three instances are now fixed (DoMINO, the shared write path, and the particle path, where the prediction is integrated twice into node positions) and whose remaining exposure is documented per process.

The profiling that settled the former C++-acceleration item — see `benchmarks/benchmark_bridges.py` for the profiling that settled the former C++-acceleration item. On 196k tets / 32k hexes the nodal gather/scatter paths cost 0.11–0.83 µs per entity, but not everything per-entity is sub-µs: element scatter-back is 2.1, grid sampling 3.5, and provenance construction 4.2 on tets and ~39 on hexes. No custom C++ adaptors are warranted even so — the dominant cost was provenance being rebuilt every step, and caching it in Python removed that.
