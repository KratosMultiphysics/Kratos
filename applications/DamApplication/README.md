### Using MPI in DamApplication ###

Note: For the moment, MPI only works in Linux and requires compiling METIS_APPLICATION and TRILINOS_APPLICATION. Non-local Damage does not work in MPI.

## Instructions to compile DamApplication for MPI (tested in Ubuntu 16.04) ##

1. Make sure that the following lines are properly set in the configure.sh file:

-DMETIS_APPLICATION=ON								                                        \
-DMETIS_INCLUDE_DIR="/usr/include/"                                                         \
-DPARMETIS_ROOT_DIR="/usr/lib/"                                                   			\
-DTRILINOS_APPLICATION=ON							                                        \
-DTRILINOS_LIBRARY_DIR="/usr/lib/x86_64-linux-gnu/"                                         \
-DTRILINOS_INCLUDE_DIR="/usr/include/trilinos/"                                             \
-DTRILINOS_LIBRARY_PREFIX="trilinos_"                                                       \
-DCONVECTION_DIFFUSION_APPLICATION=ON 						                              \
-DEXTERNAL_SOLVERS_APPLICATION=ON						                                    \
-DSTRUCTURAL_MECHANICS_APPLICATION=ON   					                                    \
-DPOROMECHANICS_APPLICATION=ON \
-DDAM_APPLICATION=ON \
-DUSE_DAM_MPI=ON \

2. Uncomment (remove #~ ) the following line in GiDInterface/Kratos.gid/apps/Dam/python/dam_main.py

#~ import KratosMultiphysics.TrilinosApplication as TrilinosApplication

## Standard output processes ##

`DamAnalysis` also accepts the standard Kratos `output_processes` block, for example
`gid_output` and `vtk_output`. The legacy `output_configuration` and
`output_device_list` blocks remain supported, so projects generated by the GiD
interface keep working without changes.

- If both `output_configuration` and a standard GiD process are configured, the
  standard GiD process is used and the legacy configuration is ignored with a
  warning. GiD output is never written twice.
- VTK output should use a dedicated folder (for example `VTK_Output`).
  `VtkOutputProcess` removes that folder at construction when
  `save_output_files_in_folder` is true and the model part is not restarted.
- Previous `.post.*` and `info.time` files are cleaned only when GiD output is
  active. VTK-only runs do not remove existing GiD results.
- VTK output is currently limited to safe nodal results. Gauss-point output for
  mixed element types and `Variable<Matrix>` results are not supported reliably
  by the standard VTK process and are not enabled automatically.
