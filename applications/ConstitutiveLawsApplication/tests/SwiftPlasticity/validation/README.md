# Swift plasticity: independent one-element FE validation

This benchmark compares a complete Kratos finite-element calculation using
`SmallStrainSwiftJ2Plasticity3DLaw` with an external ANSYS Mechanical APDL R19
calculation and an independently computed analytical uniaxial solution. It
exercises element assembly, nonlinear equilibrium, constitutive integration,
history commitment, and integration-point result extraction. It is a standalone
validation benchmark, not a constitutive-law material-point unit test.

## External reference and units

`ansys/swift_validation_ansys.csv` was generated directly by
`ansys/swift_validation_ansys.inp` using ANSYS Mechanical APDL R19. No numerical
post-processing or manual correction of the ANSYS solver results was performed.
The input header identifies R19.2. These are external validation reference data;
they are not generated by Kratos. This provenance is supplied with the reference;
ANSYS was not rerun in this environment. Both files are preserved byte-for-byte.

Units are **N, mm, MPa**; strains and accumulated equivalent plastic strain are
dimensionless. Static pseudo-time runs from 0 to 1 and introduces no rate effect.

## Model reconstructed from the APDL commands

- `ET,1,SOLID185`: one eight-node 3D brick. No `KEYOPT` overrides are specified;
  ANSYS uses its default element options. The input does not explicitly specify
  an integration rule; this README does not infer one from the CSV.
- Geometry: a 1 mm x 1 mm x 1 mm cube; connectivity `E,1,2,3,4,5,6,7,8`.
- Material 1: `MP,EX,1,EMOD`, `MP,PRXY,1,NU`, and
  `TB,PLASTIC,1,,,MISO` followed by 100 `TBPT,DEFI,p,sigma_y` entries.
- `x=0`: `UX=0`; `y=0`: `UY=0`; `z=0`: `UZ=0`.
- `x=1`: uniform prescribed `UX=0.02` mm. Other transverse displacements remain
  free. These symmetry constraints permit homogeneous lateral contraction and
  uniaxial **stress**, not uniaxial strain.
- `ANTYPE,STATIC`, `NLGEOM,OFF`, `KBC,0`, `AUTOTS,OFF`,
  `NSUBST,100,100,100`, `TIME,1.0`: one ramped load step, exactly 100 fixed substeps.
- `CNVTOL,F,,1.0E-10,2` specifies the force convergence criterion with tolerance
  1e-10 and norm option 2. The input does not override the nonlinear iteration
  limit or other solution defaults.
- `OUTRES,ALL,ALL` saves every substep. In `/POST1`, `SET,1,ISUB` and
  `ETABLE,REFL` select and refresh each result. Element 1 is read with
  `ETABLE`/`*GET`: `S,X`, `S,Y`, `S,Z`, `S,EQV`, and `NL,EPEQ`.
  `*GET,UXVAL,NODE,2,U,X` supplies displacement, with `EPSXX=UXVAL/LENGTH`.
  `*VWRITE` writes the CSV directly. These are element-table outputs; the supplied
  CSV does not expose separate ANSYS integration-point values.

`validation_utils.py` reads these numeric assignments from the authoritative
APDL input. The FE runner checks its dedicated `kratos/Materials.json` against
them before solving. This helper is specific to this benchmark, not a general
APDL interpreter. Geometry, topology and constraints are explicitly reproduced
in the runner, not parsed from arbitrary APDL commands.

## Constitutive and analytical references

Both models target infinitesimal strain, isotropic linear elasticity,
associated J2 plasticity and isotropic Swift hardening:

```text
epsilon = epsilon_e + epsilon_p
sigma = C : epsilon_e
q = sqrt(3/2 * s:s)
f = q - K*(epsilon_0+p)^n <= 0
dp = sqrt(2/3 * d_epsilon_p:d_epsilon_p)
```

Kratos uses the continuous Swift equation directly through the registered law.
ANSYS uses piecewise linear interpolation of its 100 supplied yield-stress
ordinates at equivalent plastic strains from 0 to 0.03, spaced approximately
0.03/99 apart. This is a plastic-strain/yield-stress table, not a total-strain
table. Its last point exceeds the final p of about 0.0176762; no extrapolation
is needed. The maximum discrepancy of a table ordinate from the exact Swift
equation, including printed abscissa rounding, is 6.11e-10 MPa.

For monotonic uniaxial tension, associated J2 flow gives
`d_epsilon_p_xx = dp`. Thus:

```text
sigma_y0 = K*epsilon_0^n = 398.107170553497 MPa
epsilon_y = sigma_y0/E = 0.00189574843120713
elastic: sigma = E*epsilon, p = 0
plastic: epsilon = sigma/E + p
         F(p) = E*(epsilon-p) - K*(epsilon_0+p)^n = 0
         sigma = E*(epsilon-p), q = abs(sigma)
```

The comparison script bisects the unique plastic root on `[0,epsilon]`:
`F(0)>0`, `F(epsilon)<0`, and `F'(p)=-E-H(p)<0`. It uses up to 100 bisections
or stops at floating-point bracket stagnation, then independently checks
`abs(sigma-K*(epsilon_0+p)^n) <= 1e-9 MPa`. It imports no Kratos modules and
does not reproduce the production incremental radial-return algorithm.

## Kratos FE model and solution

The selected element is **`SmallDisplacementElement3D8N`**, registered in
`applications/StructuralMechanicsApplication/structural_mechanics_application.cpp`.
It uses `Hexahedra3D8`, with the ordering above and default `GI_GAUSS_2`
(2 x 2 x 2 = eight Gauss points). The default is defined in
`kratos/geometries/hexahedra_3d_8.h` and adopted in `BaseSolidElement::Initialize`.
The run also checks that eight stresses and histories are returned per step.

This standard displacement element computes its small strain from `B*u` on
the reference geometry and supplies engineering strains to the 3D law. The
selection follows existing hexahedral examples in StructuralMechanicsApplication
`tests/test_patch_test_small_strain.py`; the solver construction follows
ConstitutiveLawsApplication `tests/test_perfect_plasticity_implementation_verification.py`.
For this homogeneous affine deformation, a standard eight-node displacement
element is sufficient; no mixed formulation or reduced integration is needed.

Solver configuration:

| Setting | Value |
|---|---|
| Strategy | `ResidualBasedNewtonRaphsonStrategy` |
| Scheme | `ResidualBasedIncrementalUpdateStaticScheme` |
| Linear solver | `SkylineLUFactorizationSolver` |
| Builder and solver | `ResidualBasedBlockBuilderAndSolver` |
| Criterion | `ResidualCriteria(1e-10, 1e-12)` |
| Maximum iterations | 30 per increment |
| Reactions | Calculated |
| Reform DOFs each step | False |
| Move mesh | False |

The residual criterion accepts a residual norm ratio <= 1e-10 **or** an absolute
norm < 1e-12 N. In this implementation the absolute norm is the residual L2 norm
divided by the number of considered DOFs, not its RMS. Both values are recorded
per increment. Density is zero because there are no body or inertial loads.

The analysis fixes only the specified symmetry and loaded-face DOFs. Eight
transverse DOFs remain free and are solved by FE equilibrium. Each step clones
time, applies `ux=0.02*substep/100`, initializes/predicts, solves, checks the
returned convergence flag, and finalizes to commit accepted history. There are
exactly 100 actual FE load levels, `epsilon_xx=0.0002,...,0.02`; no interpolation
or resampling of the Kratos result is performed.

After finalization, `element.CalculateOnIntegrationPoints` extracts
`CAUCHY_STRESS_VECTOR` and CLA's `ACCUMULATED_PLASTIC_STRAIN`. The latter reaches
the law's `Has`/`GetValue` interface through `BaseSolidElement` and is exactly
the committed p. No alternative plastic-strain measure is substituted.
The six stress components are ordered `[xx,yy,zz,xy,yz,xz]`; equivalent stress
is calculated from their full 3D von Mises invariant as result post-processing.

All eight integration-point states are retained. The runner checks per-component
spread (max minus min) <= 1e-9 MPa for stresses/q and <= 1e-14 for p before using
their arithmetic means in the main CSV. These roundoff allowances are homogeneity
checks, not fitted cross-code error bounds. Node 2 supplies `ux` and `eps_xx=ux/L`,
matching APDL. The comparison recomputes maximum spreads from the 800 point rows.

## Reproduction from the repository root

With this workspace's existing Release build and Python 3.12:

```bash
OMP_NUM_THREADS=1 \
PYTHONPATH=build/Release/kratos:build/Release/applications/StructuralMechanicsApplication:build/Release/applications/ConstitutiveLawsApplication:bin/Release \
LD_LIBRARY_PATH=build/Release/kratos:build/Release/applications/StructuralMechanicsApplication:build/Release/applications/ConstitutiveLawsApplication:bin/Release/libs \
/usr/bin/python3 -B applications/ConstitutiveLawsApplication/tests/SwiftPlasticity/validation/run_swift_validation.py

/usr/bin/python3 -B applications/ConstitutiveLawsApplication/tests/SwiftPlasticity/validation/compare_swift_validation.py
```

The build-library paths precede `bin/Release` so the current native libraries
are used with the installed Python package files. An equivalent configured
Kratos Python installation can run the same runner directly. No compilation,
package installation, or manual editing between the commands was needed here.

Both raw result CSVs have exactly:

```text
substep,eps_xx,sigma_xx,sigma_yy,sigma_zz,seqv,p_eq,ux
```

The comparison preserves those files and the APDL input, checking hashes before
and after. It reports all three pairings (ANSYS/analytical, Kratos/analytical,
Kratos/ANSYS), for sigma_xx, q and p: signed differences (first minus second),
absolute errors, relative errors, maximum absolute/relative errors and RMS
absolute errors over all 100 rows. Relative errors use the magnitude of the
second source, only if >= 1 MPa for stress/q or >= 1e-8 for p. Otherwise the CSV
cell is blank (JSON null). Relative errors are fractions, not percentages;
100 stress rows and 91 plastic-strain rows have meaningful denominators.

If matplotlib is already installed, comparison also writes
`swift_validation_stress_strain.png` and `swift_validation_plastic_strain.png`,
overlaying all three curves. Matplotlib was unavailable in the execution
environment, so these two files were not generated. No dependency was added.

## Observed results

All **100/100 increments converged**, using at most **2 Newton iterations**.
Both raw CSVs contain 100 rows with substeps 1 through 100 and end at strain
0.02. Maximum final normalized residual was 4.13975e-14 N.

| Comparison | Max sigma_xx error [MPa] | RMS sigma_xx error [MPa] | Max relative sigma_xx error [%] | Max p error [-] |
|---|---:|---:|---:|---:|
| ANSYS vs analytical | 6.20557830e-3 | 2.22530710e-3 | 1.54404128e-3 | 2.96004448e-8 |
| Kratos vs analytical | 3.84318355e-10 | 9.98629554e-11 | 9.42742315e-11 | 2.00468982e-15 |
| Kratos vs ANSYS | 6.20557830e-3 | 2.22530717e-3 | 1.54406512e-3 | 2.96004448e-8 |

Equivalent-stress maximum errors are the same to the displayed precision;
the full metrics, including p RMS/relative errors, are in the summary JSON.

| Transverse stress maximum [MPa] | abs(sigma_yy) | abs(sigma_zz) |
|---|---:|---:|
| ANSYS raw element-table output | 1.09996413e-12 | 1.19662827e-12 |
| Kratos integration-point average | 1.40968126e-10 | 1.40978784e-10 |
| Kratos over every individual integration point | 1.41056944e-10 | 1.41056944e-10 |

Maximum spreads over Kratos integration points were 1.93267624e-12 MPa across
the six stress components, 9.09494702e-13 MPa for q, and 1.04083409e-17 for p.
The homogeneous uniaxial-stress state is therefore supported by the FE results.

At epsilon_xx = 0.02:

| Source | sigma_xx [MPa] | q [MPa] | p [-] |
|---|---:|---:|---:|
| Analytical | 488.0015915460365 | 488.0015915460365 | 0.017676182897399827 |
| ANSYS | 488.00057983398 | 488.00057983398 | 0.017676187679172 |
| Kratos | 488.00159154603983 | 488.0015915460398 | 0.017676182897399813 |

The observed ordering agrees with the expected MISO interpolation effect.
As a separate diagnostic, the comparison bisects the uniaxial equation using
the *supplied piecewise linear table*. This reduces ANSYS's maximum axial-stress
discrepancy to 1.52538094e-5 MPa (RMS 8.35993605e-6 MPa). Thus table interpolation
explains nearly all of the difference from continuous Swift. ANSYS stresses
are within 5.01e-12 MPa of representable float32 values, and its p values within
4.90e-16 of float32 values. The remaining discrepancy is consistent with output
quantization; this is an inference from the supplied numbers, not a claim about
ANSYS's internal solver arithmetic. No raw data are rounded or corrected here,
and the diagnostic MISO law is never used in the Kratos FE calculation.

## Limitations

This checks one homogeneous monotonic uniaxial loading path with infinitesimal
kinematics. It does not validate general multiaxial/nonproportional FE loading,
unloading, mesh convergence, finite strain, damage, fracture or localization.
It does not establish equivalence of all SOLID185 and Kratos element options.
ANSYS integration-point homogeneity cannot be checked separately from its
element-table CSV. The external ANSYS result was consumed, not regenerated.
Errors are reported as observed; no cross-code acceptance thresholds were tuned.
Production constitutive files, variables and material-point tests are unchanged.
